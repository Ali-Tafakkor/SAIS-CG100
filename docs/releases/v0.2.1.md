## Ethernet installation and updates

Download **SAIS-CG100-Programmer-win-x64.zip**, extract the complete folder, and run
**Run-Programmer.cmd**. The Windows runtime, OpenOCD, recovery service and main
firmware are included; no separate Python installation is needed.

- Choose a small initial bootstrap through ST-LINK followed by the main application
  through Ethernet, or choose complete SWD installation.
- Prepared boards accept later firmware updates through Ethernet alone.
- Per-board authenticated requests and responses, image hashing, A/B trial boots,
  automatic rollback and an independent network recovery service.
- Opt-in fleet update worker for computers with LAN/VPN access to installed boards.
- Corrected automatic browser startup, visible error logs, an in-page review form,
  measured transfer progress and saved reports.

Firmware: **3.3.0-dev-netinstall**. Recovery: **1.0.0-recovery**. Update protocol: **2**.

## Verification

31 host tests and 13 tests of compiled ARM firmware logic pass. On one supported
board, both initial installation routes passed. With SWD physically removed,
testing covered a changed firmware version, cold boot, 16 admission/corruption
checks, rollback after two unconfirmed trials, power loss with an incomplete
transfer, a subsequent update, and the maximum 4,190,208-byte application image.

The normal 135,384-byte image transferred in about 1.9 seconds. The maximum-size
image transferred in 53.4 seconds. These figures include NOR writing/readback and
are specific to this board; they are not a guaranteed Ethernet/SWD speed ratio.

This is a development/manufacturing pilot for MainBoard v2.6 / STM32H750 with the
documented NOR and SDRAM. Multiple-board deployments, routed networks, production
secure boot and precisely timed power cuts need further qualification. Read the
operator guide and qualification record included in the ZIP before field use.

Keep the board access file and memory backups private. Automatic updates require
an explicitly enabled board and a running updater on a reachable site computer.

## Build correction

The v0.2.0 tag passed firmware compilation and 31 host tests, but its release job
stopped because the ARM test step did not inherit the compiler path from the build
step. No v0.2.0 binary release was published. v0.2.1 sets that path explicitly;
firmware and installer behavior remain identical to the qualified source.
